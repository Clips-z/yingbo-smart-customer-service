# 统一三平台伴随面板设计

## 目标

将现有千牛专用伴随面板扩展为一个通用面板，自动跟随当前前台客服平台：千牛、微信或企业微信。面板必须始终明确展示当前平台和客户，保留各会话历史与草稿，并在上下文不可信时禁止填入，避免跨平台或跨客户误操作。

## 窗口与吸附

- 支持 `win_qianniu`、`win_wechat`、`win_wecom` 三种目标。
- 优先跟随当前前台客服窗口；用户操作迎波主程序或伴随面板时保持上一个可信目标。
- 前台目标稳定约 800ms 后才切换，避免 Alt+Tab 或弹窗导致抖动。
- 支持自动跟随与手动锁定平台；锁定后只跟随指定平台的主聊天窗口。
- 分平台保存左右吸附偏好，兼容多显示器、DPI 缩放、最小化和恢复。
- 自由悬浮时不移动窗口，但内容仍可跟随当前平台。
- 迁移旧的 `qianniu-companion-state`，不丢失原有用户设置。

## 会话数据

微信和企微复用现有 OCR Sidecar。每轮识别将当前联系人、最近消息、账号/企业、置信度和采集时间报告给后端。后端统一生成 `平台 + 账号/店铺 + 联系人` 会话键，并使用稳定切换、旧请求隔离和同会话缓存策略。

快速 `A → B → A` 时恢复 A 的最近 2–3 段对话和编辑草稿。相同客户消息复用已有回复，不重复请求模型。不同平台即使联系人同名也不能共享上下文或草稿。

## 安全规则

- 切换中、识别失败、内容沿用或前台平台不匹配时禁用填入。
- 填入前再次校验平台、联系人和会话版本。
- “仅人工”只展示草稿；“辅助”只填入输入框；“自动”沿用现有独立开关，不因吸附功能自动开启。
- 微信群聊和企微群聊继续遵守现有私聊与 `@我` 过滤。
- 旧请求晚返回时不得覆盖新客户草稿。

## 界面

标题显示平台和身份，例如“微信 · 张三”“企业微信 · 王经理”“千牛 · wheeltec旗舰店 / 买家”。千牛保留商品卡片；微信和企微无商品时隐藏该区域，为历史和草稿腾出空间。

状态统一为切换中、已稳定、内容沿用、识别失败。提供“跟随当前窗口 / 锁定微信 / 锁定企微 / 锁定千牛”和左右吸附控制。

## 性能与发布

只对当前前台平台执行伴随上下文高频刷新，后台平台保留原有低频消息采集。正式打包前检查三平台脚本、Python、OCR 与 RAG 运行时完整性。版本显示统一读取 Electron 应用版本，不再维护独立常量。

## 验收

- 三平台前台切换和手动锁定。
- 每个平台 `A → B → A` 历史与草稿恢复。
- 最小化、关闭、重启、多显示器、DPI 和左右吸附。
- OCR 延迟、失败、旧响应晚返回和平台关闭。
- 辅助模式绝不自动发送。
- 单元测试、生产构建、Python 编译和三平台本机只读实测通过。
