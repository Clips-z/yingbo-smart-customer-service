# v1.5.1 可移植运行时与采集修复设计

## 目标

v1.5.1 必须能在未安装 Python 的干净 Windows 电脑上直接安装和运行。微信 4.x、千牛 OCR 与 RAG 使用随软件发布的 Python 3.11 运行时，不再依赖构建电脑上的绝对路径或可迁移性较差的 Windows venv 启动器。

## 方案选择

采用“共享 Python 解释器、隔离依赖目录”的方式。发布包包含 `resources/tools/python311`，微信、千牛和 RAG 分别使用独立的第三方依赖目录，避免 RapidOCR、NumPy、OpenCV 等版本互相污染。构建脚本负责下载固定版本的 Python 3.11 embeddable runtime，并按锁定的 requirements 安装依赖；运行时服务直接调用内置解释器，脚本在导入第三方包前加入对应依赖目录。

没有采用复制 Windows venv 的方案，因为 `pyvenv.cfg` 会保留构建机的绝对 Python 路径，正是 v1.5.0 在其他目录启动失败的根因。也不把约 360 MB 的二进制运行时提交到 Git，而是通过可重复的准备脚本生成，并在打包前、打包后各做一次完整性检查。

## 行为修复

微信 sidecar 显式加入脚本目录，确保隔离模式下可导入 `_retry_utils.py`。千牛 OCR 收紧聊天候选区域、允许中文买家名，并允许安全的后台窗口消息在千牛前台时切换未读会话。RAG 固定 `onnxruntime==1.20.1`，并禁用不兼容的 PostHog 遥测调用。

首次启动若检测到千牛进程但没有 `win_qianniu` 任务，后端自动补建本地兼容任务与激活配置，保证识别到的消息不会因任务表为空被丢弃。该初始化必须幂等，不重复创建已有任务。

## 验证与发布

单元测试覆盖运行时路径、默认任务幂等初始化和千牛 OCR 筛选规则。发布前检查源运行时目录，发布后检查 `win-unpacked/resources` 中解释器、依赖、脚本和 RAG 服务文件，并实际调用内置 Python 导入 RapidOCR、微信依赖、ChromaDB 与 ONNX Runtime。最终版本号更新为 1.5.1，生成 NSIS 安装包和 win-unpacked 目录，并通过 GitHub Release 发布。
