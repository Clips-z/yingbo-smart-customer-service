# 持久化知识库与运营工作台设计

## 目标

将商品问答库和店铺知识库从前端内存模拟数据升级为 SQLite 持久化功能。数据在软件重启、版本升级和界面刷新后仍然存在，并能向 RAG 索引报告真实同步状态。

## 数据与接口

新增商品知识和店铺问答实体。商品包含名称、平台商品 ID、条码、店铺、标签、上下架状态、问答数和同步状态；店铺问答包含问题、回复、相似问法、业务阶段、店铺、标签、启用状态和同步状态。后端提供分页、搜索、新增、编辑、删除、批量状态和批量删除接口。条码和平台商品 ID 按非空值唯一性校验，问题和回复必须在长度限制内。

## 同步与失败语义

数据库是唯一真实来源。保存成功后再尝试更新 RAG；RAG 失败不回滚用户已保存的内容，而是将记录标记为 `pending` 或 `failed`，保存可诊断的错误摘要，并允许重试。只有启用且同步状态正常的内容可进入自动检索。

## 界面方向

使用现有 Chakra 组件体系，统一为紧凑、高可读性的运营后台。页首显示真实总数、启用数和待同步数；表格将业务标识、状态和批量操作保持在稳定位置。空库不注入演示数据，而是引导用户新增或导入。不使用强动画和大面积渐变，把操作速度、误删防护和状态反馈放在第一位。

## 验证

单元和集成测试覆盖数据库初始化、CRUD、分页搜索、唯一性、批量操作、RAG 同步失败和重启后恢复。界面验证覆盖空状态、加载、错误、批量操作和分页。最后运行全量 Jest、主进程和渲染进程生产构建。
