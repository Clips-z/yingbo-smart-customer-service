# 左侧聚合接待工作台设计

## 目标

把现有主窗口增加为三种可随时切换的形态：完整运营工作台、左侧聚合接待台与自由悬浮接待台。程序每次启动默认进入左侧模式，识别到当前客服平台后跟随其左侧，与右侧伴随助手形成对称；完整模式继续承载质量分析、知识库、平台管理和设置。

## 方案选择

评估过三种方案：

1. 新建独立接待窗口：隔离清晰，但会产生第三个窗口以及两套状态同步。
2. 把伴随助手同时兼作左侧接待栏：窗口更少，但客户问答与账号/队列职责混杂。
3. 复用主窗口并切换紧凑布局：数据源一致、窗口数量不增加、恢复成本最低。

采用第三种。主进程保存完整模式窗口尺寸，进入左侧模式时通过同一套平台窗口探测服务定位到当前客服客户端左边；尚未识别到客户端时先停靠在当前屏幕左边。恢复时还原原尺寸和位置。

## 界面与数据流

紧凑模式顶部展示“左侧吸附、自由悬浮、展开大屏”和刷新按钮。左吸附会持续跟随当前平台；自由悬浮保留紧凑布局但停止自动移动，可由用户拖到任意位置。主体有“聚合接待”和“账号连接”两个标签：

- 聚合接待按待回复/已回复筛选多平台回复建议，突出店铺、客户、问题摘要和等待时间。点击待回复卡片会激活对应平台、切换到该客户并把焦点留在输入框；不会写入或发送任何内容，定位结果直接显示在列表顶部。
- 账号连接按平台分组显示运行状态和已配置客服实例。

列表数据直接复用现有平台、任务和回复建议接口，不创建第二套缓存。点击客户或账号会先导航到完整模式对应页面，再恢复大屏。

## 回答填入

回答卡片点击后依次校验回复模式、采集状态、客户身份和最新问题，再调用平台填入接口。周期 OCR 刷新造成的版本号和像素指纹变化不再视为客户切换；店铺、账号、客户、商品或最新问题变化仍会拦截。成功与失败原因直接显示在回答卡片下方，杜绝点击后无反馈。

## 验证

- TypeScript 类型检查。
- 会话填入安全校验、伴随助手选择、窗口吸附单元测试。
- 生产构建与 Windows unpacked 桌面包生成。
- 实机确认左侧模式、双标签和恢复大屏。
