## 产品定位与布局原则

- 主控制台：面向店主、主管和运营人员的宽屏后台，负责总览、批量处理、知识治理和配置。
- 伴随助手：贴靠千牛、微信等客服窗口的窄屏操作面板，负责查看建议、编辑和填入。
- 店铺与平台是多对一关系：一个平台可配置多个店铺；统一工作台可跨平台、跨店铺筛选。
- 默认只展示完成当前任务必需的信息，技术诊断、检索证据和低频危险操作按需展开。

## P0：落地阻断与核心工作流

### 1. 伴随助手稳定性

- 修复开发环境 preload 路径错误导致的 `window.electron` 缺失和整窗崩溃。
- IPC 不可用时显示可恢复的错误状态，不能白屏或进入开发错误页。
- 验收：开发版和打包版均能打开助手；贴靠、折叠、平台切换和填入操作可用。

### 2. 主工作台主从布局

- 主控制台默认使用适合后台的宽窗口，消息列表与回复详情同屏。
- 小尺寸窗口保留纵向布局，但限制列表高度，避免详情被推到不可发现的位置。
- 列表负责“找下一条”，详情负责“判断并处理”，两区有明确边界和独立滚动。
- 验收：1280×800 下不需要页面级滚动即可完成选消息、改回复、填入；窄屏无横向溢出。

### 3. 批量操作安全性

- 高频选择与“标记已处理”保留在主操作区。
- 删除、清空等不可逆操作进入“更多操作”，仍保留二次确认和明确影响数量。
- 没有可操作对象时禁用操作；处理中禁止重复提交。
- 验收：用户不会因主操作区按钮拥挤误触清空；确认框说明对象、数量和结果。

### 4. 运行状态与模式安全

- 当前平台、店铺、回复模式和采集健康状态必须在首屏可见。
- 无人值守使用高对比持续警示，并始终提供“立即停止”。
- 采集异常给出恢复动作，不只显示技术错误。

## P1：界面和操作体验

### 1. 导航与信息架构

- 桌面宽屏支持带文字的可折叠主导航；窄屏保留图标导航和工具提示。
- “数据与统计”不得表现为普通页面却突然打开新窗口，应增加外开标识。
- 店铺切换器统一放在全局上下文区，平台筛选作为次一级条件。

### 2. 工作台减负

- 默认折叠 OCR、召回分数、证据编号等技术信息，集中到“回复依据”抽屉。
- 消息卡首屏只保留客户、平台/店铺、等待时间、原话和状态。
- 将排序、筛选、批量选择整合为一条自适应工具栏。

### 3. 状态与反馈

- 补齐加载骨架、空状态、断线、部分失败、权限不足和可重试状态。
- 所有保存、导入、导出、填入和删除操作提供结果与下一步。
- 长任务展示进度；Toast 不承载必须阅读的失败原因。

### 4. 可访问性与效率

- 图标按钮全部具备可读名称；键盘焦点清晰；危险色不是唯一状态提示。
- J/K 切换仅在列表聚焦时生效，并在首次使用时提示。
- 正文与辅助文字达到可读对比度，主要操作点击区域不小于 36px。

## P2：产品化增强

### 1. 新手引导与角色化首页

- 首次启动向导：连接平台 → 创建店铺 → 导入知识 → 测试回复 → 开启辅助模式。
- 店主、主管、客服看到不同的默认指标和快捷任务。

### 2. 质量闭环可视化

- 展示命中率、采用率、编辑率、拦截率、平均处理时长及趋势。
- 从低分回复一键进入知识候选，保留来源对话、适用店铺和审核记录。
- 知识库继续支持查看、搜索、手动编辑、批量导入和导出。

### 3. 设计系统和交付质量

- 统一间距、圆角、字体层级、表单密度和状态色，减少页面间样式漂移。
- 建立关键页面视觉回归、异常状态测试和可用性验收清单。
- 发布包增加迁移、备份恢复、崩溃日志和版本回退说明。

## 实施顺序

1. 修复伴随助手崩溃。
2. 调整主窗口尺寸与工作台双栏可用性。
3. 收敛批量危险操作。
4. 完成 P0 的类型检查、测试、构建和人工走查。
5. 按导航、信息减负、状态反馈、可访问性的顺序推进 P1。
6. 以真实使用数据决定 P2 的仪表盘和自动积累策略。
