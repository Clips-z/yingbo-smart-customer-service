# 千牛无障碍探测与原文复制兜底实施计划

**目标：** 在不依赖淘宝开放平台、不修改千牛进程、不持续全屏 OCR 的前提下，提高自用场景的识别准确率和响应速度。

**已确认决策：** 先对当前千牛客户端做只读 UIA/MSAA 探测。只有同时稳定读取当前客户、聊天消息和输入框时，才切换无障碍主链路；否则保留可读取的客户/商品上下文，并改为“一键读取剪贴板原文并生成”。

## 通过门槛

- 能唯一确定当前千牛接待台窗口。
- 能唯一确定当前店铺和客户，而不是只列出后台驻留的多个店铺页面。
- 能读取可见聊天消息正文及方向。
- 能定位真实输入框。
- 连续切换客户时不复用上一客户的上下文。

缺少“消息正文”或“输入框”任意一项，均不得把 UIA/MSAA 设为千牛主采集源。

## 当前实机证据（2026-08-03）

- 客户端：AliWorkbench/Qianniu `9.98.28N`，聊天渲染进程为 `AliRender.exe --render_id=bench_im-*`。
- UIA Raw View 可以看到 Qt 顶层窗口、`CefBrowserWindow`、`Chrome_RenderWidgetHostHWND`，但 Chrome Legacy Window 下没有聊天正文和输入框。
- MSAA 可以读取右侧智能客服/订单 Web 页中的买家昵称、商品标题、商品 ID、价格、订单状态等结构化文本。
- MSAA 暴露了多个后台驻留店铺页面，不能仅凭“买家昵称”节点判断当前激活店铺。
- 中央聊天区只暴露 AI 咨询摘要 Web 页；客户聊天气泡和输入框没有出现在 UIA/MSAA 树中。

**判定：部分通过，不允许切换为 UIA/MSAA 消息主链路。**

## 实施步骤

### 任务 1：固化只读探针

- 新增 `scripts/probe-qianniu-accessibility.ps1`。
- 枚举千牛接待台、UIA Raw View 和 MSAA 树。
- 输出能力布尔值和节点统计；URL 查询参数、session key、签名等敏感内容禁止写入报告。
- 运行时不点击、不输入、不发送、不关闭或重启千牛。

### 任务 2：增加探测结果模型和诊断

- 后端解析探针 JSON，区分 `uia-active`、`accessibility-partial`、`clipboard-assisted`。
- 伴随助手只显示用户可理解的状态：`结构化增强`、`复制原文生成`、`OCR 兼容`。
- 部分通过时可以使用商品结构化数据，但不得把后台驻留客户误报为当前客户。

### 任务 3：实现“一键读取原文并生成”

- 用户在千牛中复制客户问题后，点击伴随助手“读取复制内容并生成”。
- 后端读取剪贴板文本，去除空白、限制长度并拒绝与上一次完全相同的误触。
- 使用当前稳定会话身份创建人工来源的客户问题；人工来源不受 OCR 置信度限制。
- 切换客户后旧回复继续通过 `contextRevision` 失效，不能填入新客户。

### 任务 4：填入与自动模式

- 点击回答卡仍复用现有填入链路。
- 辅助模式只填入；自动模式只在身份校验通过后增加发送。
- 剪贴板问题只解决“问题原文准确性”，不放宽跨客户保护。

### 任务 5：验证

- 自动测试：探针能力判定、剪贴板清洗、重复问题、客户切换、旧草稿失效。
- 实机：A 客户复制生成 → B 客户复制生成 → A 客户；文字、链接、长文本各至少 10 次。
- 验收：复制文本准确率 100%，不串客户，点击回答可填入当前千牛输入框。

## 明确不做

- 不复制多脉二进制、私有协议或凭据。
- 不注入或修改 `AliWorkbench.exe` / `AliRender.exe`。
- 不把右侧商品页的多个后台买家昵称当作当前激活客户。
- 不再以提高 OCR 字符识别率作为核心路线。
