# 平台支持状态

本文档用于区分“已接入”“可实测”和“仍在开发中”的平台能力，避免交付时把实验性入口误认为完整可用功能。

## 状态说明

- **可用**：已有运行链路，适合进入日常测试和小范围使用。
- **部分可用**：已有检测或消息采集能力，但辅助回复、无人值守发送等关键动作仍需补齐。
- **开发中**：保留入口或脚本雏形，暂不建议作为交付承诺。

## 支持矩阵

| 平台 | 当前状态 | 说明 |
| --- | --- | --- |
| 微信 | 可用 | 已有 sidecar 启动脚本和探测脚本，可作为优先验证平台。 |
| 千牛 | 可用 | 已有兼容服务、OCR worker 和布局配置，是当前重点支持平台之一。 |
| 企业微信 | 部分可用 | 有 sidecar 和窗口识别逻辑，建议继续补充端到端实测记录。 |
| 京麦 | 部分可用 | 已有 sidecar 脚本，但无人值守自动填入/发送仍有 TODO。 |
| 拼多多 | 开发中 | sidecar 脚本中定位填入和自动发送仍标记为 TODO。 |
| 抖音飞鸽 | 开发中 | sidecar 脚本中辅助回复定位仍标记为开发中。 |

## 交付建议

1. 对外演示优先使用微信和千牛。
2. 企业微信、京麦可以作为“内测支持”说明。
3. 拼多多和抖音飞鸽在 TODO 清零前，不建议标为正式支持。
4. 每个平台进入“可用”前，至少补齐一次端到端验证记录：启动、识别联系人、生成回复、填入/发送、异常恢复。
