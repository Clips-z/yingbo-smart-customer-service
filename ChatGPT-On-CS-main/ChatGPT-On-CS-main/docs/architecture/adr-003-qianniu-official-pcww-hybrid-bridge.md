# ADR-003：千牛官方 PCWW 桥接与按变化 OCR 混合链路

- 日期：2026-08-03
- 状态：Accepted（真机启用等待千牛应用测试权限）

## 背景

千牛 `AliRender` 进程没有继承普通 Chromium 远程调试参数，常见 CDP 端口无法连接。因此，外部 CDP 不能作为当前版本的稳定结构化通道。旧实现还在 250ms 常驻截图循环中执行 Windows OCR，导致客户切换、问题识别和回复生成前置等待明显变慢。

千牛官方 PCWW/H5 JSSDK 提供当前联系人变化、当前联系人读取和向输入框插入文本的公开能力，但第三方应用不能依赖已经下线的完整聊天消息事件。

## 决策

采用以下混合链路：

1. 常驻 PowerShell 进程以 150ms 间隔检查会话区域指纹；相同指纹不执行 OCR，并复用上一次结构化结果。
2. 指纹发生变化后，在同一常驻进程内执行一次 Windows OCR。RapidOCR 只作为低置信度或运行时故障的复核通道，不再阻塞正常回复主链路。
3. 已安装并获得测试权限的千牛 PCWW 页面通过官方 JSSDK 上报 `securityUID + bizDomain + userNick`。
4. 点击 AI 回答时，优先通过官方 `insertText2Inputbox` 填入，并在操作前重新读取、校验当前联系人。
5. 官方桥接只负责身份和填入，不实现自动发送；自动发送继续受现有会话一致性和幂等保护约束。
6. 官方桥接未连接时保留现有坐标/OCR 兼容通道，诊断信息必须明确显示实际采集源。

## 安全与边界

- 不注入千牛进程，不复制或逆向第三方助手私有协议。
- 不把普通外部 CDP 描述为可用能力。
- 不使用已下线的第三方完整消息监听接口。
- 不允许官方填入命令跨客户执行，也不在失败后自动重复发送。

## 实测证据

- 当前千牛版本：`AliWorkbench 9.98.28N`。
- 普通外部 CDP：不可连接，详见 ADR-002。
- 常驻纯指纹采集：热态相同画面约 259–295ms，`ocrEngine=none`，OCR 调用数为 0。
- 常驻 Windows OCR：进程启动后的识别间隔约 394–514ms；相比之下，RapidOCR 首次约 5.2 秒、预热后仍约 2.9 秒，因此不能放在实时主链路。
- 问题筛选以最新入站气泡为准，仅排除“好的/收到/谢谢”等明确结束语，不再要求问号或“吗/么”。
- 相关自动测试：官方联系人、心跳、命令队列、填入前身份校验、页面脚本语法和纯指纹启动参数均已覆盖。

## 尚未满足的发布门槛

官方桥接的真机启用需要千牛开放平台 PCWW 应用的 AppKey、测试账号和页面投放/回调权限。获得权限后仍需完成：

- A 店客户 1 → A 店客户 2 → A 店客户 1 的连续切换测试；
- 多店铺切换与点击回答填入 100 次，串客户和错填均为 0；
- 8 小时稳定运行；
- 官方桥接断开时兼容通道接管和恢复测试。

在这些门槛通过前，不能把“官方结构化链路已真机可用”写入发布说明。
