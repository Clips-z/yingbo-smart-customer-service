# 迎波智能客服使用手册

版权所有 © 2026 YinBo

## 1. 软件用途

迎波智能客服用于统一管理微信、千牛、京麦和企业微信等客服工作台，根据实际启动的平台采集顾客消息并生成回复建议。

## 2. 首次使用

1. 启动迎波智能客服，并允许本机网络访问。
2. 打开需要接待的平台客户端并完成登录。
3. 在左侧平台列表中确认对应平台显示“在线”。
4. 点击“设置 → AI 配置”，选择大模型类型并填写连接信息。
5. 点击“检查连接”，确认模型能够正常返回测试内容。
6. 返回主界面，选择回复模式后启动自动回复。

## 3. 回复模式

- **仅提示**：只在回复工作台生成建议，不操作聊天窗口。
- **辅助回复**：点击“填入”后定位联系人并把建议写入输入框，由人工确认发送。
- **无人值守**：自动定位、填写并发送。建议先在测试账号中验证后再启用。

微信与千牛可以同时运行。主界面会按平台分别显示任务与状态，未启动的平台不会进行识别。

## 4. AI 配置

### OpenAI 兼容模型

适用于 OpenAI、通义千问兼容接口和其他兼容服务：

- 大模型类型：选择 `OpenAI`
- 模型：填写服务商提供的模型名，例如 `qwen-turbo`
- API 地址：填写以 `/v1` 结尾的兼容地址
- API Key：填写服务商密钥

客服人设和本地知识库会应用到普通模型回复中。

### Coze 智能体

1. 在 Coze 中将智能体发布到 API 渠道。
2. 在“大模型类型”中选择 `Coze 智能体`。
3. 选择中国区或国际区。
4. 填写 Personal Access Token 与 Bot ID。
5. 点击“检查 Coze 连接”。

Coze 模式直接使用智能体内的人设、知识库、插件和工作流，不再叠加本地提示词。

## 5. 平台工作台

- 平台显示“在线”后才会采集消息。
- 每个平台拥有独立的回复任务列表和模式。
- “待回复”表示尚未处理；“已处理”表示已填入、发送或忽略。
- 点击微信回复卡片的“填入微信”会尝试定位对应联系人，而不是直接写入当前聊天。

## 6. 关键词与转人工

- 关键词匹配可优先使用固定话术。
- 关键词转人工会停止自动回复并提醒人工接管。
- 关键词替换可在发送前替换敏感表达。
- 修改规则后建议用测试消息验证命中结果。

## 7. 日志与排查

- 每次启动会清理界面中的旧运行日志。
- “打开日志文件”可查看完整记录。
- 平台离线：检查客户端是否启动、登录状态和版本兼容性。
- 模型连接失败：检查 API 地址、模型名、Key、余额和网络。
- Coze 拒绝访问：重新创建 Token，并确认智能体已发布到 API 渠道。
- 微信定位失败：确认联系人名称可搜索、微信已登录且未处于锁定界面。

## 8. 安全建议

- 不要在截图、聊天或日志中公开 API Key、Coze Token。
- 首次启用无人值守前，先使用仅提示和辅助回复验证话术。
- 涉及退款、价格承诺、售后争议时建议设置转人工规则。

## 9. 数据位置

配置和回复记录默认保存在：

`文档\chatgpt-on-cs\msg.db`

为避免原有配置丢失，升级后仍沿用该数据目录。

## 10. 打包前检查

平台自动化和消息采集依赖 Python 后端可执行文件。源码仓库默认不提交该二进制产物，打包前需要确认以下任一路径存在：

- `assets/backend/__main__.exe`
- `release/app/assets/backend/__main__.exe`

可运行下面的检查命令：

```bash
pnpm run check:backend
```

正式打包会使用强制检查：

```bash
pnpm run package
```

如果只是在本地调试，也可以通过 `BKEXE_PATH` 指向已有的后端可执行文件。

## 11. 开发与打包命令

首次拉取源码后安装依赖：

```bash
pnpm install
```

开发环境如需生成 renderer DLL，可手动执行：

```bash
pnpm run prepare:dev
```

正式打包前，先确认 Python 后端产物存在，然后执行：

```bash
pnpm run package
```

`package` 会自动执行：

1. 检查后端可执行文件。
2. 构建主进程和渲染进程。
3. 复制 sqlite3 等运行时原生依赖到 `release/app/node_modules`。
4. 生成安装包。

平台支持状态见 `docs/platform-support.md`。
